## Outcome
Integrate DEV-7's placement selector into Project scheduling under the existing mutation lock. Depends on the configuration/selector follow-up; use DEV-7's capability contract. Remote execution remains unavailable until its adapter is implemented.

## Acceptance Criteria
- [ ] Reserve machine and launch identity durably before emitting worker.spawn. Count reserved/spawning, running and unknown external executions across every Board in this sf Project. Preserve one live Claim per Story. Ignore unrelated/manual and historical idle threads.
- [ ] Drain oldest eligible entries, skipping pinned/full/unavailable entries without blocking later eligible work. Config, override, capability refresh, completion and reconciliation wake the queue. A lowered capacity never kills running Workers and prevents new reservations until usage drops below it.
- [ ] Extend Claims, Worker records, commands and structured results with stable environment/project identity, owning worktree/branch, launch/request identity and task/thread identity. Keep legacy local records/results readable; define conservative migration for existing live records.
- [ ] Separate Claim validity from execution occupancy. Move/release invalidate the old Worker's authority immediately; external capacity is freed only on confirmed completion/termination. Timeout/force-release/cancel with uncertain external state retains an occupied unknown reservation. Next Stage cannot concurrently reuse the same Story branch while the old execution is unconfirmed.
- [ ] Confirmed preparation/spawn failure frees its reservation; uncertain launch response is reconciled with its durable idempotency identity, never blindly relaunched. A temporary disconnect/restart does not create a second local copy. Define reconciliation ownership, cadence and safe operator recovery for irreconcilable tasks; do not offer force-forget that silently undercounts a live execution.
- [ ] Inject an execution adapter/fake at the Supervisor boundary; policy remains in sf. Non-T3 adapters expose local support and explicit unsupported-remote reasons. No machine network calls while holding the mutation lock; apply reconciliation results only to matching launch generations.
- [ ] Service tests cover simultaneous requests, multiple Boards, eligible FIFO, all overrides, cancellation races, stale command responses, Claim expiry, restart/reconnect and lost-launch responses. Existing local-only behavior remains covered.

## Refinement

### Outcome

Dispatch uses DEV-9's pure selector and a durable per-Project execution ledger. Concurrent requests across Boards cannot reserve the same slot or run two Workers in one Story branch. Losing a launch response, a Claim, or the Supervisor connection cannot silently free occupied capacity or cause a duplicate launch. Remote targets remain explicitly unsupported until DEV-11 provides a verified adapter. DEV-7 and DEV-9 are Done; their delivered report/ADR and merged policy implementation have been reconciled on 2026-10-31. The dependency gate is satisfied. This Story is Ready for development after updating its older branch to the current base.

### Scope

In: atomic reservation and publication recovery; eligible FIFO; Claim/execution separation; versioned runtime migration; correlated command/result and reconciliation protocol; local compatibility adapter and injected fake; lifecycle tests and Supervisor protocol documentation.

Out: remote transport/authentication/worktree setup (DEV-11), configuration/editor/placement controls and polished status/recovery UI (DEV-12), host-wide quotas, load balancing and autonomous branch recovery. Minimal structured runtime status and safe recovery command/API documentation are included because operators must be able to diagnose an occupied unknown execution.

Keep the ledger, dispatch and reconciliation in one coherent PR: splitting Claim separation from occupancy or publication recovery would leave an unsafe intermediate scheduler. No additional Story is needed; the existing DEV-11/12 slices retain transport and product integration.

### Acceptance Criteria

- [ ] Consume `normalizePlacementPolicy`, `selectPlacement`, `StoryPlacement`, `PlacementPolicy`, `TargetEligibility`, `PlacementReason` and `PlacementResult` from delivered `src/model/placement.ts`; do not implement another selector. Call `selectPlacement(policy, placement, eligibility, usage)`, with explicit `{ failures: [] }` evidence for eligible local execution and explicit `incompatible` detail for unsupported remote execution. Missing evidence is incompatible, including local. Retain ordered eligibility priority (`missing-target`, `disabled`, `incompatible`, `unreachable`, `unauthorized`, `unmapped`, `agent-ineligible`, `model-ineligible`) ahead of capacity; keep `capacity` and `no-candidates` unchanged. Add branch-occupied/reconciliation wait diagnostics at the scheduler layer rather than changing the pure selector contract. Without scheduling use local and legacy maxConcurrentWorkers/default 3; with scheduling use only per-machine caps across all Boards. Preserve all override ordering, eligibility-before-capacity and missing-target reasons. In production this slice never selects a remote as eligible; fakes may simulate eligible targets without network launches.
- [ ] Persist one execution entry per immutable launch generation with worker/Story/Board/Stage identity, machine ID, stable environment/Project identity, owning worktree path/branch, launch/request ID, command ID, lifecycle timestamps and task/thread IDs when known. Distinguish reserved/preparing/launching, running, unknown and confirmed terminal states. Only nonterminal entries occupy capacity; Claim authority and command completion are independent. Use stable persisted local identities, not pid, display name, URL or path alone; use the delivered opaque environment/project IDs and exact catalog `repositoryIdentity.canonicalKey` mapping; never derive identity from display names, routes or checkout paths. Persist a generated sf environment identity for a local adapter lacking a public environment ID, and a generated sf Project identity in authoritative runtime storage; namespace these separately from adapter IDs. Retain verified adapter environment/project IDs alongside them when available; do not manufacture T3 IDs or silently replace the identity namespace on reconnect. Local identity survives restart and path changes; remote configuration retains DEV-9’s `{ id, name, environmentId, project: { projectId, repository }, enabled, capacity }` shape without new transport/config fields. Treat an environment or project mapping change under an occupied machine slug conservatively: retain the old slot charge and branch fence, and block new launches on that slug until the old execution is terminal. Machine removal/renaming cannot hide old occupied entries or release their Story branch fence.
- [ ] Under the existing cross-process mutation lock, select and reserve capacity, create at most one Claim, and persist a launch publication intent before exposing worker.spawn. Dispatch after commit and outside the lock. Treat runtime state as the authoritative outbox and deduplicate Store publication by immutable launch identity. A crash before/after state save, enqueue, session save or acknowledgement recovers the same intent/command; it never creates a new launch identity. Existing split runtime/session persistence must not expose a command without its saved reservation. Make session writes atomic and propagate persistence failure without freeing uncertain occupancy.
- [ ] Queue entries retain enqueue order (timestamp plus stable tie-breaker). Each drain visits oldest entries first, discards obsolete/deleted/disabled/HIL-held requests as appropriate, and skips entries with unavailable/full required targets or an occupied Story branch while continuing to later eligible entries. Repeated drains do not duplicate requests or reset their age. A newer Move replaces the prior request for that Story. Route new requests through the same ordering so they cannot jump older eligible work. Decrement available capacity via reservations during the same transaction. Lowered caps prevent new reservations without stopping existing executions.
- [ ] Wake dispatch after configuration/placement edits, capability refresh, confirmed execution completion, applied reconciliation, startup and the existing periodic sweep. File configuration changes must reach this path as well as service updates. Revalidate current Stage, prompt/HIL, dependency readiness, resolved agent/model, Claim, placement and generation before reservation and after asynchronous preparation. Any selection invalidated before external dispatch must be cancelled safely rather than launched against a stale request.
- [ ] Move, release, force-release and Claim timeout immediately revoke Worker command authority using the existing claim_gone rejection. They do not prove external completion. Keep occupancy and the owning Story branch fenced until confirmed terminal; queue a next-Stage request without preparing/reusing/removing its worktree while that execution is live or unknown. Apply the fence to Done cleanup and explicit ensure/remove actions too. A Worker reporting Move/release while its thread is still winding down cannot overlap a next-Stage Worker. Late launch success may attach execution identity to its matching old reservation but cannot restore its Claim or overwrite a successor's state.
- [ ] Distinguish confirmed pre-dispatch/preparation failure from uncertain external launch. A confirmed never-dispatched failure can free its reservation and record the existing spawn failure; post-dispatch timeout/disconnect/cancel acknowledgement alone becomes unknown unless the adapter proves terminal. Duplicate/late done, fail, cancel and reconciliation reports are idempotent and generation-checked. Conflicting terminal reports require authoritative reconciliation, never a new Claim. Cancelled command records must still accept correlated execution evidence without regaining Worker authority; current StoreService.cancel/finish behavior must not discard the only task identity.
- [ ] Extend command/API/CLI results with a validated structured execution envelope (generation/request identity, machine/environment/Project, worktree/branch, execution status and task/thread IDs). Define launch-accepted separately from execution-terminal. Retain legacy result/error strings for reading and legacy Supervisor compatibility; launch success is never completion. A legacy failure is definite only when known to occur before dispatch; otherwise preserve unknown occupancy. Ignore/reject mismatched identities and stale generations without mutating the current Claim/reservation. Ordinary supervisor.instruct result behavior remains unchanged.
- [ ] Provide an injectable boundary contract for eligibility, preparation/launch reporting, lookup by durable request or task identity, status and cancellation. sf owns capacity, queue and Claim policy; the Supervisor owns tool execution. Communicate through durable correlated commands/results where external tools are only accessible to the Supervisor. Network/tool calls and worktree preparation run outside the mutation lock; apply results in a new mutation only if the launch generation and reconciliation attempt still match. Concurrent stale polls cannot overwrite newer terminal evidence. Non-T3 adapters advertise local support and concrete unsupported remote/status/idempotency reasons; unsupported status never means completed.
- [ ] The online service owns reconciliation scheduling, issuing at most one outstanding attempt per execution at startup/reconnect, on relevant results and every existing sweep interval. The Supervisor executes boundary requests; reconnect never blindly replays a claimed worker.spawn as a fresh launch. Use the same request ID only when the adapter guarantees idempotency. When launch lookup or idempotency is unavailable (including a lost response from a top-level launch), retain unknown and require explicit recovery; never assume generic not-found proves no execution. No automatic retry with a new ID or local fallback while an execution may exist. Bound external requests and persist retry timestamps/attempt identities so restart does not create concurrent reconciliation storms.
- [ ] Migration is versioned, durable and repeatable. Legacy live Claims/Workers become occupied local entries with generated-and-persisted launch identities and branch fences; known external IDs are retained, missing/ambiguous IDs become unknown. Legacy claimed/pending spawn records are matched to their Worker, not automatically treated as safe to launch again. Historical ended records without a live Claim or unresolved spawn intent remain history, not new occupancy. Document that older endedAt records meant Claim end and cannot retrospectively prove external termination; conflicting unresolved launch evidence takes precedence. Do not count unrelated/manual threads or scrape all provider history as capacity.
- [ ] Expose diagnostic execution identity/status/wait reason through structured service/runtime results and document recovery. An operator can reconnect/lookup an execution, request cancellation, or provide correlated confirmed-terminal evidence through the supported authenticated Supervisor protocol. No force-forget or elapsed-time action may release an unconfirmed execution. If an adapter cannot establish completion, keep the reservation/fence and report exactly what evidence is missing; DEV-12 provides the eventual UI. Document local adapters without observable completion and the resulting conservative wait rather than claim universal automatic recovery.
- [ ] Add deterministic fake-adapter/service and HTTP/CLI persistence tests covering parallel requests across Boards, cap 0 and reductions, all placement modes and skipped FIFO entries, every wake source, failures at publication crash boundaries, cancellation during preparation/dispatch, Move/release/timeout authority revocation with retained occupancy, deferred Done cleanup, stale/duplicate/mismatched results, migration reloads, restart/reconnect and response-lost launch adoption. Assert at most one launch per request, no branch overlap and no unconfirmed capacity release, including remote simulations with production remote disabled. Update local-only regression tests for the intentional distinction between Claim end and execution end. Run focused tests, pnpm test and pnpm check during development; no real remote execution is required here.
